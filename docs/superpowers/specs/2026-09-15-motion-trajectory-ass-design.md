# 移动文字轨迹 → ASS 轨迹字幕 设计(阶段一:手动触发全链路)

- 日期:2026-09-15
- 状态:已评审批准(方案 A + 两步走)
- 前置:`core/scene_plane_tracker.py`(平面单应跟踪,已落地未接线)、
  `core/ocr_optimizer.py` `_fuse_samples_by_position`(按位置对齐投票,已落地)、
  背景分析 `test/phone-scene-analysis-20260915/analysis.md`(阶段二遗留项 #2)

## 1. 背景与问题

以 `test/[DMG] 冴えない彼女の育てかた♭ 第07話19.mp4`(1920×1080,24000/1001 fps,
246 帧)的手持手机邮件场景为例,当前产出的 ASS 把移动的场景文字切成大量
0.2~0.4 s 的静态 `\pos` 短段(~263 条事件),伴随:

- **跳格**:每个时间段内文字固定不动,段间跳位;
- **重复**:同文本同时间段出现多条事件(帧分组按 `MERGE_POS_TOLERANCE=20px`
  切开、事件合并按 `SCENE_POS_TOLERANCE_PX=24px` 又合不回来);
- **碎片垃圾**:运动模糊帧被强行 OCR,产出「藤とさ」「早亲め最」「SEMY」类
  碎片读法;另有零时长事件。

根因:位置容差驱动的分组/合并模型把「移动」当成了「不同字幕」;文字内容与
几何位置未解耦。

## 2. 目标 / 非目标

### 目标(阶段一)

给定 视频 + 手动框选的平面四边形(quad)+ 时间范围,产出跟随移动的 ASS
轨迹字幕,并在上述手机场景完成验收。核心原则:**逐帧跟踪几何,关键帧识别
文本**——OCR 只在清晰关键帧上做并投票,位置由逐帧单应跟踪提供。

### 非目标(后续阶段)

- 移动文字的自动检测触发(本阶段仅预留检测器接口,输入一律手动指定);
- GUI 四角框选/关键帧修正入口;
- `\iclip` 手部遮挡蒙版、屏幕调暗变色;
- 镜头切换显式状态(现有跟踪器 lost 质量门限已兜底);
- 原字擦除/背景重建。

## 3. 技术决策与依据

| 决策 | 依据 |
| --- | --- |
| `\t()` 不用于位移 | VSFilter/libass 中 `\t` 只能动画可动画标签(`\frz/\frx/\fry`、`\fscx/\fscy`、`\fs\c\alpha\bord\clip` 等);`\pos`/`\move` 写进 `\t` 被忽略。位移只能用 `\move`(两点线性)或离散 `\pos` |
| 非线性轨迹用分段 `\move` | `\move` 只支持两点匀速直线;将逐帧轨迹按误差预算简化为若干直线段,每段一条事件,段间端点精确相接即视觉无缝。匀速直线是单段退化情形 |
| 旋转/缩放用 `\t` 补充 | 单应分解出的每帧角度/缩放,在段内用 `\t(t1,t2,\frz..\fscx..\fscy..)` 线性插值 |
| 帧级 `\pos` 仅作兜底 | 24fps 离散更新视觉上平滑,但事件数爆炸(本例约 2200 条)且继承 OCR 框抖动;仅当分段后仍超误差预算时使用 |
| OCR 不逐帧做 | 运动模糊帧 OCR 产生碎片垃圾(现状 .ass 已证实);内容几乎不变,逐帧需要的只是几何。关键帧投票文本 + 逐帧跟踪位置 = 又稳又准 |
| 复用 scene_plane_tracker | 已实现 ORB+RANSAC 单应、质量门限、lost 重捕获、正/逆单应、轨迹 JSON;正好是「逐帧几何」的供给方 |

## 4. 数据流与模块

```
视频 + quad + [t0,t1](手动输入,CLI)
  │
  ├─ core/scene_plane_tracker.track_plane()      已有:逐帧单应+质量门限
  │     → List[TrackedQuad](ok/lost,含正/逆单应、time_sec)
  │
  ├─ 新增 core/keyframe_selector.py
  │     从 ok 帧选 top-K(默认 3)清晰关键帧:
  │     unwarp_canonical 展开图文字区域 Laplacian 方差(清晰度)排序
  │
  ├─ 关键帧 OCR(统一坐标)
  │     展开到关键帧平面坐标后 OCR → 行框/文本/置信度
  │     复用 ocr_optimizer._fuse_samples_by_position 按位置对齐投票
  │     → 每行:平面坐标行框 + 稳定文本 + 置信度
  │
  └─ 新增 core/motion_ass.py(轨迹→ASS 合成器,纯函数,可单测)
        输入:轨迹 + 关键帧行 + 配置 → 输出:ASS 事件列表(dict,同 generator 事件结构)
```

### 4.1 行轨迹重建(motion_ass 内)

- 任两帧间单应:`H(k→t) = H(init→t) · inv(H(init→k))`(tracker 已逐帧保存
  相对 init 的累计单应;lost 帧无轨迹点,行轨迹在该帧记缺失)。
- 对每个投票行框取四角点,逐帧映射到 t 帧 → 行四边形 → 中心
  (均值)、角度(`atan2` 于长边)、缩放(长边长度比)。
- 每行独立成事件链;行间相对位置变化由各自轨迹覆盖,不需 `\org`。
- 关键帧 k 若 lost,取最近 ok 帧 k′,行框经 `H(k→k′)` 换算到 k′ 平面
  坐标系后再参与映射(链乘即可)。

### 4.2 关键帧 OCR 与融合

- OCR 在 `unwarp_canonical` 展开图上运行(统一坐标,识别最稳);
- 关键帧间行对齐与投票复用 `_fuse_samples_by_position`(缺失观测不投票);
- 融合输入适配为 `rec_texts/rec_scores/rec_boxes/rec_polys` 结构;
- 行框保留在平面坐标系,输出阶段才映射回画面。

## 5. 标签阶梯(motion_ass 核心逻辑)

按顺序判定,命中即停:

1. **平滑**:中心/角度/缩放序列滑窗(默认 5 帧)去抖;仅去高频抖动,
   不改运动趋势(超窗缓慢趋势保留)。
2. **分段候选**:位移 Douglas-Peucker 简化(容差 `move_tol_px=2.0` @1080p)
   得分段点;并入角度变化 ≥`rot_thresh_deg=1.0`、缩放变化 ≥`scale_thresh=0.02`
   的显著点;强制最小段长 `min_seg_frames=3`。
3. **单段直线**:全程对首末连线最大偏差 ≤ 容差 → 一条事件
   `{\an5\move(x1,y1,x2,y2,t1,t2)}`(t1/t2 为相对事件开始的毫秒,取 0 与段长)。
4. **分段 `\move`**:每段一条事件;相邻段 `end_time == 下一段 start_time`
   (同一格式化字符串,杜绝 centisecond 舍入产生的 1 帧缝隙/重叠);
   段起止角度/缩放超阈值时叠加 `\t(\frz(a)\fscx(..)\fscy(..))`(ASS 语义:
   段内从当前值线性动画到目标值)。
5. **帧级 `\pos` 兜底**:DP 保证每段偏差 ≤ 容差,但混乱手持抖动会使段数
   爆炸(平均段长 < `min_seg_frames` 的 2 倍,或每秒段数 > 6)→ 对该区间
   改按帧级 `\pos` 兜底(平滑后隔 1~2 帧抽稀输出),比几十条微型 `\move`
   事件更干净。几何误差预算 = `move_tol_px`;渲染误差预算见 DoD。
6. **lost 间隔**:默认切段(事件在 lost 前结束,恢复后以恢复帧轨迹重新
   开始),不外推;可选 `lost_hold_sec=0.0`(>0 时 ≤该时长的 lost 用
   前段末位保持);零长段(<1 帧)丢弃。
7. **合并豁免**:阶段一脚本直写事件,不经过 `_merge_temporal_near_duplicate_events`
   与 `_clamp_same_roi_event_overlaps`(时间轴已由合成器保证有序相接);
   事件带 `Name: motion` 标记,供阶段二并入主流水线时作为合并豁免依据。
   事件按行组织,同一文本同一时刻只有一条链。

### 5.1 默认参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `move_tol_px` | 2.0 | DP 简化/单段判定容差(1080p 像素) |
| `min_seg_frames` | 3 | 最小段长(~0.125s @24fps) |
| `smooth_window` | 5 | 滑动平均窗口(帧) |
| `rot_thresh_deg` | 1.0 | 分段点/`\t` 叠加的角度阈值 |
| `scale_thresh` | 0.02 | 缩放变化阈值 |
| `keyframe_count` | 3 | 清晰关键帧数 |
| `lost_hold_sec` | 0.0 | lost 保持时长(0=切段) |
| `dense_pos_fallback` | true | 允许帧级 `\pos` 兜底 |

## 6. 管线接入(阶段一形态)

- CLI/脚本旁路,不动主流水线:
  - `scripts/track_plane.py`(已有)产轨迹 JSON;
  - 新增 `scripts/motion_ass.py`:`--video --quad-file --start --end
    [--trajectory] [--out]`,串接 跟踪→关键帧选择→OCR→融合→合成→写 .ass;
  - 产出独立 .ass,与现状 `test/*.ass` 对比验收。
- 主流水线(GUI/roi_editing 集成、自动检测触发)按两步走策略留阶段二。
- 检测器接口预留:`motion_ass` 与合成逻辑不依赖「quad 来源」;阶段二的
  自动检测器(采样 OCR 行心位移超阈值触发)只负责产出 quad+时间范围。

## 7. 与现状输出的关系

- 轨迹事件**替代**(非叠加)该 quad 时间范围内的碎片 `\pos` 事件;
- 阶段一产出独立文件,不改 `generator.py` 的既有事件路径;
- 模糊帧碎片因「不对模糊帧 OCR」自然消失;
- 真实存在的画面文字(如按钮水印「SEMY」)若关键帧可读则保留且位置正确;
  内容取舍归 `text_source_classifier`/水印过滤既有职责,本设计不扩权。

## 8. 验收标准(DoD)

1. 本视频手动 quad 全程(0~10.26s)跟踪,产出 .ass:
   - 同一文本无重复事件链;无模糊碎片读法;
   - 事件数从 ~263 降至约 40±20 条(11 行 × 分段数);
2. 新增渲染校验脚本 `scripts/verify_motion_ass.py`:ffmpeg(libass)烧录
   抽样帧,字幕中心与跟踪四边形中心偏差:中位 ≤4px、95 分位 ≤8px;
   超预算段自动加密分段重试一次,仍超则报警;
3. 0~3s 慢漂移段与 8.9~9.8s 快速移动段人工抽查贴合;
4. 单元测试:合成卡片平移/缩放/旋转、单段退化、lost 切段、`\t` 输出、
   段边界时间连续性、时间格式往返;全量 pytest 无回归。

## 9. 风险与限制

- **遮挡期文字消失**:lost 切段后遮挡期间不显示(阶段一如实呈现并在
  事件 `Name` 标注区间;`\iclip` 蒙版属阶段三);
- **非整数帧率**:全程使用 `TrackedQuad.time_sec` 浮点,仅格式化时取
  centisecond;
- **关键帧间行数不一致**:投票层缺失观测机制已覆盖,不阻塞;
- **透视极限**:任意透视形变不能靠 `\frx/\fry` 精确重现;强透视场景由
  渲染校验暴露,超出预算时按帧级 `\pos` 兜底(仍超则标注人工复核);
- **\move 毫秒取整**:t1/t2 取整到 1ms,段长 ≥3 帧(~125ms),误差可忽略。
